# Дерево Перков с Ветвями и сбросом раз за Престиж

Статус: принято (реализуется в слое 1 плана `docs/plans/deepening.md`); правит ADR-0004 в части «Наследия поколений».

Список из 23 Перков стоил 437 Compute и закрывался к 3–4-му Престижу; дефицита не было, и порядок покупок почти не влиял. «Наследие поколений» — 220 из 437 Compute — почти ничего не давало: Перк прошлого Поколения не влияет на текущий Забег, а свой можно купить только при Флагмане, то есть когда Забег уже выигран (`docs/research/07-current-depth-audit.md`).

Решение: Перки образуют дерево из общего ствола и трёх Ветвей под стили игры — «Промпт-инженер» (Клик), «Оркестратор» (Агенты и Оффлайн-доход), «Оверклокер» (Температура и риск). Взаимоисключающие только верхние Перки Ветвей: глубоко можно пойти по одной, неглубоко — по двум. Раз за Престиж дерево бесплатно сбрасывается, а Compute возвращается, поэтому ошибка не навсегда (как в Trimps). «Наследие» уходит в ствол в переделанном виде.

## Considered Options

- **Оставить список, поднять цены и добавить Перков** — отклонено. Дефицит появляется, а выбора нет: оптимальный порядок покупок пишется один раз.
- **Слоты активных Перков** — отклонено. Это второй источник сборки рядом с Курсом, и он скрывает купленное.
- **Взаимоисключение на всю глубину Ветви** — отклонено. Наказывает гибридную игру без выигрыша в выборе.

## Consequences

- Миграция с bump `SAVE_VERSION`: id Перков, ушедших из каталога, при загрузке превращаются в Compute по их цене через `computeSpent`, а не пропадают молча, как `migrate` делает сейчас.
- Вместе с ADR-0010 сброс делает решение «копить или тратить Compute» обратимым, а значит интересным, а не страшным.
- Дерево живёт в подразделе «Перки» вкладки «Престиж» (её разбивка — #85); оверлей ADR-0005 остаётся анимацией и выбора не содержит.
