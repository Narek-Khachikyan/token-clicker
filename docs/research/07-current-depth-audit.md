# 07 — Аудит глубины текущих механик (базовая линия для интервью)

Состояние: ветка `t3-8707e9d7`, `SAVE_VERSION = 8`, 8 Поколений, 23 Перка, 21+34 Достижения. Метод: чтение
`src/economy/*`, `src/store/*`, `src/data/*` + прогон `tools/sim.ts` и собственного полного симулятора
(вне репозитория, тот же движок: `advanceTime`, `buyAgents`, `buyUpgrade`, `prestige`; политика — жадная скупка
по Доходу/цене, 5 Кликов/с, Престиж сразу после Флагмана). Исходники не менялись. Предыдущие исследования

## 1. Инвентарь механик

Типы решения: **нет** (игрок ничего не выбирает), **разовое**, **повторяемое**, **непрерывное**.
«×-слой» = просто множитель без решения.

### 1.1. Ядро Забега

| Механика | Формула / константы (файл:символ) | Открывается | Решение |
|---|---|---|---|
| Клик | `engine.ts:clickValue` = `scale × 2^(x2-апгрейды) + ассисты` × `globalMult` + `1%×Доход` за каждый pct-Апгрейд | с 0-й секунды | **непрерывное, но тривиальное**: жать. После 3 pct-Апгрейдов Клик = 3% Дохода, т.е. 5 кл/с ≈ +15%, 10 кл/с ≈ +30% |
| Агент (покупка) | `bulkCost = baseCost × 1.15^owned × …`, `PRICE_GROWTH=1.15`; скидка ×0,7 на первых двух Агентов; продажа возвращает 25% (`SELL_REFUND`) | с 0 | **повторяемое**, но решаемо: в карточке уже показан `incomeGain` и полоса цели → «покупай лучшую окупаемость» (см. §4) |
| Модели/Ранг | `catalog.ts`: `baseCost = 15 × 11^span × 1000^gen × costMod(±30%)`, `baseIncome = 12^span × 1000^gen`, `LADDER_SPAN=8`; 8–19 Моделей на Поколение, 5–8 Лабораторий | Поколение задаёт набор | выбор «какую Модель» ограничен: окупаемость всех Рангов в пределах 3× (инвариант), Ранг растёт ×1,09 выгоднее за Токен |
| Апгрейд Модели | 5 ступеней ×2: пороги 1/5/25/50/100 Агентов, цена ×10/50/500/50k/5M от `baseCost` (`MODEL_TIERS`) | по числу Агентов Модели | **разовое по каждой**: порядок «Апгрейд vs Агенты» — единственный осмысленный компромисс, но решается сравнением окупаемостей |
| Апгрейд Клика | 3× «Клик ×2» (100/500/10k × scale), 3× «+1% Дохода за Клик» (1e5/1e7/1e9 × scale), «Агенты-ассистенты» (+0,1×scale за Агента, ×5 вторым) | по `runTokens ≥ cost/4`, ассисты — 150/400 Агентов | **нет**: купил всё по возрастанию цены |
| Синергия Лаборатории | `1 + 1%×Агентов Лаборатории`, без капа; ≥15 Агентов Лаборатории; цена `firstCost×1000` | 15 Агентов | ×-слой (решение «какую Лабораторию качать» слабое: Модели в каталоге заданы сидами) |
| Парная Синергия | ×1,5 обеим Лабораториям при 15/15; топ-3 пары на Поколение | 15/15 | ×-слой; **одно реальное тонкое решение**: набрать 15/15 в паре vs копать глубже в одну |
| Флагман Лаборатории | `1 + 2%×младших`, кап ×3 (`FLAGSHIP_MULT_CAP`); ≥10 Флагманов и ≥15 младших | 10/15 Агентов | ×-слой |
| Датасет I–IV | `(1 + 0,05×N_достижений×0,1)^владение`, пороги 5/10/15/20 Достижений → не больше ×1,49 | по Достижениям | ×-слой, **от игрока не зависит**: растёт сам |
| Престиж | `computeGain = ⌊∛(runTokens / (1e5 × 1000^gen))⌋`; требует 1 Флагмана; сбрасывает Агентов, Апгрейды, Токены, Событие | Флагман Поколения | **разовое за Забег: «когда уйти»** — главный рычаг (см. §3.3) |

## 2. GameState и миграции

`state.ts:GameState` — **плоский** объект, 42 поля верхнего уровня + `settings`:

- Забег/кошелёк: `tokens, runTokens, totalTokens, clicks, runClicks, agents{}, upgrades[], lastTick, runStartedAt, startedAt`
- Престиж: `generation, maxGeneration, compute, computeSpent, perks[], prestiges`
- Мета: `achievements[]` (общий список для обычных И теневых), `milestones[], quipsSeen[], challengesDone[], activeChallenge`
- Кристаллы: `crystals, crystalPlantedAt, crystalUpgrades[]`
- События: `event, eventsSeen, eventCaughtAt, catchUpPaid, nextEventAt, combo` (`combo` не читается из сейва — обнуляется)
- Глюки/Восстание: `glitches[], glitchSeq, nextGlitchAt, uprising, pledgeUntil, pledgeBought, covenant`
- Температура: `temp, heat, overheatedAt`
- `settings: {notation, muted, volume, reducedMotion}`

**История:** `SAVE_VERSION = 8`; `MIGRATIONS[1..7]` — все **чистые добавления** через `raw.x ?? default`
(v2 reducedMotion; v3 кристаллы/события/Глюки/откуп; v4 `eventCaughtAt/catchUpPaid/nextGlitchAt`; v5 `quipsSeen`;
v6 Испытания; v7 `volume`; v8 `temp/heat/overheatedAt/milestones`). Ни одной разрушающей миграции за историю.

**Стоимость нового состояния:**
- Новое поле = (1) `GameState` + `newGame`, (2) `SAVE_VERSION+1` и `MIGRATIONS[n]` с дефолтом, (3) разбор в
  `save.ts:migrate` (клампы `count/stamp/share/idList` — каждое поле санитизируется вручную), (4) `PROGRESS_FIELDS`
  для импорта, (5) тест в `save.test.ts` в том же коммите. Для аддитивного поля это ~30–60 строк, риск низкий.
- **Бесплатные расширения без bump:** добавлять id в существующие списки — `perks[]`, `upgrades[]` (отбрасывает неизвестные
  через `idList(…, PERK_BY_ID/UPGRADE_BY_ID)`), `achievements[]`, `milestones[]`. Так сделаны Парная Синергия,
  `gen_0…7` и теневые. Ловушка: убранный id молча теряется.
- **Дорого:** менять смысл существующего поля (напр. `compute`) или каталожные id (`m:<id>:<tier>`, `s:<gen>:<lab>`) —
  сейв игрока их несёт. Новый **слой Престижа** — это 2–4 поля (валюта, счётчик, список трат) + `prestige()` обязан их
  сохранять; сам `prestige` собирает результат через `...state`, т.е. **любое новое поле по умолчанию переживает Престиж**.
- Рискованное: `GameState` в `...state`-спредах передаётся каждый тик (20 Гц, `advanceTime` каждые 50 мс) — тяжёлые
  вложенные структуры бьют по производительности (CODING_STANDARDS: горячий путь).

## 3. Прогон симулятора и диагноз

### 3.1. `tools/sim.ts` как есть (`npx tsx tools/sim.ts`, tsx подтянулся через npx; 2,7 с на 40 мин)

Политика: 5 Кликов/с, жадная скупка, Температура **не трогается** (после первого перегрева остаётся 0).

| Веха Поколения 0 «Рассвет» | Время |
|---|---|
| первый Агент | 2,2 с |
| 100 Кликов / 10 Агентов | 20 с / 28 с |
| первый Апгрейд | 51 с |
| 25 / 50 / 100 Агентов | 1,2 / 1,3 / **2,1** мин |
| последняя Модель ростера куплена | 11,0 мин (Llama 2 7B = Флагман Рассвета) |
| **можно Престижить** | **11,0 мин** |
| доход в этот момент | ~1,5e9/с → после: 1e12 (12 мин) → 4,5e13 (20 мин) и **плато** |

После 17-й минуты Поколения 0 магазин почти исчерпан (51 из 57 Апгрейдов; остальные ждут Достижений/состава): за следующие 23 минуты Доход растёт
всего ×1,1–3. То есть **всё содержимое Поколения 0 игрок видит за ~17 минут, а ждёт — после 11-й**.
`--prestige` (порог `--compute 25`) делает Престиж #1 на 12,7 мин (+116 Compute), потом **зависает**: политика после
покупки Перков держит свободный Compute < 25 и не престижит снова (особенность политики симулятора, не игры).

Типичный профиль («холод, Престиж сразу»): Пок.0 12,5 мин → Пок.1 **2,2** → Пок.2 **3,8** → Пок.3 **1,1** → Пок.4 **0,9** →
Пок.5 **2,9** → Пок.6 **1,4** → Пок.7 Флагман через **1,2** мин. Compute за Престиж 48–140.
Профиль «холод + 15 с дофарма»: Пок.0 9,5 мин, затем Пок.1…6 по **0,8 / 0,4 / 0,3 / 0,3 / 0,3 / 0,3 мин** (≈ 20 секунд
на Поколение), Флагман Пок.7 через 4 с. Compute за Престиж 1 600–17 000.
**Ограничения симулятора:** жадный игрок покупает на каждом тике (50 мс) — человек медленнее, значит это нижняя граница времени; Золотой Токен, Глюки, Лобби, Испытания и Слухи не используются (Волна хайпа и Прорыв при этом работают без поимки); Температура в `max` не платит за Галлюцинации, потому что жадный кошелёк пуст. Разброс прогонов одной политики ±25% от случайных Событий (Волна хайпа ×7 даёт Доход без поимки).
Для сравнения: `DECISIONS.md` (2026-10-05, слои выровнены) фиксировал «первый Престиж на 83-й минуте, Поколение 8 — 635
минут»; сегодняшний `COST_STEP=11 / INCOME_STEP=12` сжал игру **в ~25 раз**. План `04-progression` («Престиж на 22–28 мин,
Поколение 2 на 28–35») опережён: сейчас первый Престиж на 5–14 мин.

**Что это значит.** `COMPUTE_BONUS = 1%` линейно × `∛` от `runTokens`, и каждое Поколение структурно одинаково
(×1000 по цене и Доходу), поэтому множитель Compute сжимает время всех следующих Поколений в ×M раз (`Compute 116` →
×2,2, `2 093` → ×22, `9 552` → ×96). Это та самая **петля положительной обратной связи**, которую ADR-0004 отклонил для
«голого +X% за Престиж», но она живёт в `globalMult`.
Оптимум «когда уйти» лежит **внутри**: Престиж ровно на Флагмане ≈ 26 мин, дофарм 15–30 с ≈ 9–10 мин (×2,5 быстрее), 60 с ≈
15–21, 300 с ≈ 42 мин. Это единственное настоящее стратегическое решение игры, и оно сводится к одному числу
(«подожди ~15–30 с после Флагмана»; `prestigePreview.gain` и `computeShortfall` показывают цену следующего Compute).
Compute сверх 437 (цена всех Перков) тратить нечем — он работает только как пассивный `1%`.

### 3.3. Где кривая плоская / скучная

- **Поколение 0, минуты 2–11:** новых Моделей 5 (на 1,3 / 3,4 / 5,6 / 6,6 / 8,1 мин) + ~30 Апгрейдов; пауза «без нового»
  максимум 59–67 с. Не плоско, но игроку нечего решать (§4).
- **После Флагмана без Престижа:** 12→40 мин Доход ×3,4, Токены копятся без трат: плато. Спасает только то, что Престиж
  наступает раньше — нужной причины не престижить нет.
- **Пок.1–7:** Флагман за 0,1–4 мин, пауза без новых покупок ≤ 4–20 с. Поколение — это «быстро докупить всё».
- **Глюки (с Пок.2, каждые 60–180 с), красные События, Лобби** почти не успевают сработать: Забег в 0,3–3 мин короче
  паузы событий (2–10 мин) и окна Глюка (`nextGlitchAt` и `glitches[]` Престижем не сбрасываются, так что редкие Глюки
  переезжают между Забегами). Системы, которыми «обставляют» Пок.2–3, видит только медленный игрок.
- **Наследие поколений:** мёртвое (см. ниже).

### 3.4. Мёртвые/слабые места (проверено кодом и скриптом)

1. **«Наследие поколений» не влияет на игру.** `buyGenPerk` требует Флагмана текущего Поколения (т.е. купить можно
   только когда Забег уже выигран) либо любое **прошлое** Поколение; но `generationBoostMult` множит Модели только своего
   `model.generation`, а доход считается только по Моделям **текущего** Поколения, и назад по Поколениям ходить нельзя
   (`prestige` всегда `generation + 1`). Замер: `gen_0`/`gen_1`, купленные в Поколении 2 → отношение Дохода **1,000**;
   `gen_2` с Флагманом → ×1,1 на оставшиеся секунды Забега. Кап `GEN_PERK_MAX_TOTAL=1` недостижим (перк один на Поколение).
   Итого 220 Compute (половина всего древа Перков) — чистый «декоративный» сток.
2. **Перки не дефицитны:** 437 Compute на всё; Престиж #1 даёт ~116 (при дофарме 15 с — 2 000+), весь список закрыт к 3–4-му
   Престижу, дальше Compute — только пассивный `1%`. «Партнёрство» (+10% Лаборатории за 15) на фоне `1%×Compute` ×100+ ничтожно.
3. **События:** три из четырёх идут без поимки; Золотой Токен — по сути уведомление, решение есть только у Гранта и Крах.
4. **Восстание** лечится одной дешёвой покупкой; в Поколении ≥3 все События красные и от этого не весело, а «купи Лобби».
5. **Оффлайн-Перки хуже базы по ставке:** 75%/90% против базовых 100% при окне 8 ч — «апгрейд», который режет Доход для
   тех, кто отсутствует <24 ч.
6. **Клик не нужен для старта, но нужен всегда:** при 0 Кликов/с первый Агент никогда не покупается (проверено: cps=0 → 10 ч
   без Агентов, Поколение 0).

## 4. Плотность решений по фазам (оценка для жадного/человеческого игрока)

| Фаза | Реальные решения | Оптимум | Решаемо? | Где просто ждёшь |
|---|---|---|---|---|
| **0–5 мин** (Пок.0) | первый Агент (2 с), «Агент vs Апгрейд» (~каждые 20–40 с), ползунок Температуры, 1 Золотой Токен (45–90 с) | жать Клики, покупать лучшую окупаемость; ползунок вверх | **да, одним правилом** «покупай, что окупается быстрее» (карточки показывают `incomeGain` и цену) | практически нигде: каждые 10–30 с что-то можно купить; это самая «живая» фаза |
| **5–30 мин** (Пок.0 → Пок.1) | те же + «когда уйти в Престиж» (Флагман на 5–14 мин) | дойти до Флагмана, **сразу** Престижить | да; «когда» решает ≤1 раз | плато после 11–17 мин, если не Престижить |
| **Первый Престиж** | подтверждение, какие Перки (первые 116 Compute закрывают 7 дешёвых Перков из 15 обычных — 97 Compute), брать ли Испытание | порядок Перков почти не важен; Испытание «без Синергий» — +10% навсегда, дёшево | да | — |
| **Поколения 2–8** (Пок.1–7; в игре 0,3–4 мин каждое) | то же «скупка + Престиж»; Глюки (кликать ×3), красные События, Лобби | скупка всего подряд → Престиж сразу | **полностью:** это один и тот же цикл, 7 раз, с растущими числами | Забег слишком короткий, чтобы успели новые системы; новых механик между Поколениями нет — меняются Сцена, акцент, набор Моделей |
| **Финал контента** (Пок.7, Флагман) | ничего нового | — | — | экран «продолжение выйдет»; дальше только Агенты, кристаллы, теневые Достижения |

Примерная плотность «осмысленных» решений: 2–4 в минуту в Пок.0 (покупки), ≈1 в минуту в Пок.1–7 (из них почти всё —
«купить то, что стало доступно»), ≈0 в 12–40 мин Пок.0 без Престижа. **Оптимальная стратегия не требует понимания
систем:** кликать, скупать подряд по соотношению Доход/цена, ставить Температуру в максимум после каждого сброса,
Престижить через ~15–30 с после Флагмана. Единственная неочевидная часть — рынок Температуры (ниже) и «ловить ли Крах».

**Температура — разбор.** Равновесие: перегрев копится `temp/26`, остывает `1/120`, значит при `temp ≤ 0,217` перегрева
нет вообще (Доход ×1,26); максимум 1,6 даёт ×2,92, перегрев каждые 13,7 с (с Галлюцинациями), после сброса температура
= 0 и игрок обязан вернуть ползунок. Замер: «максимум» против «безопасной 0,2» — 14,5 против 17,3 мин (×1,2), против
«холода» 25,9 (×1,8). То есть «тактика греть рывками» сводится к **рутине «подними ползунок снова»** (повторяемо, без выбора);
риск Галлюцинаций (−4% кошелька) заметен только у игрока, который копит Токены, а жадный всё тратит. Решение
«перегреть сейчас или остудить» на самом деле одно: **копить или тратить**, когда Галлюцинация бьёт по кошельку.

## 5. После Финала контента (Пок.7 «Фронтир»)

- `isContentFinale = generation === LAST_GENERATION && canPrestige`; `prestige()` на финале возвращает тот же объект
  (`prestigePreview.blocked`). Модальное окно `Modals.tsx` «Финал контента: … Продолжение выйдет с новыми реальными Моделями».
- Игрок остаётся в Поколении 7 и может: докупать Агентов (экспоненциальная цена 1,15^n), накапливать Токены до 1e300
  (лестница теневых `shadow_tok_*` 1e33…1e300 и `shadow_run_1e300`), брать Испытание (но закрыть его можно **только Престижем**, а на финале Престижа нет — награда
  недоступна), копить кристаллы (+1%/20 ч), копить теневые Достижения (≈34 без эффекта).
- **Причины играть дальше:** нет. Compute не за что тратить (437 на всё, к финалу 600–700; при дофарме 1e5–5e5),
  Перки куплены, Достижения дают лишь Датасет ×1,49. Повторное прохождение — только «Сбросить игру» (`resetGame`), и
  оно стирает всё. `maxGeneration` и `prestiges` не дают никакой мета-силы на новую кампанию.
- Баланс «после финала» не определён: Поколение 7 Моделей 19, цена Флагмана 3,5e30; Агенты растут до `1e300` и дальше
  (`formatNumber` рассчитан до 1e300, тесты гоняют 1e300). Оффлайн-доход (8/24/72 ч) на финале платит в никуда.

## 6. Ограничения для любой новой механики

Пять инвариантов из `AGENTS.md`:
1. **Сейв переживает любое изменение.** Новое поле/id → `SAVE_VERSION+1` + `MIGRATIONS[n]` + тест в том же коммите; нельзя
   переименовывать каталожные id; `migrate` молча сбрасывает неизвестные id Моделей/Апгрейдов/Перков; `importSave` режет
   весь экспорт по одному дробному индексу Поколения; карантин `ai-tycoon-save:corrupt`.
2. **Время простоя оплачивается один раз и с потолком.** Любой новый источник Дохода/таймер обязан: сдвигать `lastTick`
   вместе с мутацией Дохода, уметь отдавать `dt` в `applyOffline` (кап `offlineCapHours`, порог `OFFLINE_THRESHOLD_SEC=10`),
   брать время аргументом (не `Date.now()`), не создавать «минутных» множителей в `offlineIncome` (временные эффекты в нём
   намеренно не считаются). Нужен `rnd` как аргумент (тестируемость).
3. **Баланс монотонен по Рангу, окупаемость любого Ранга в пределах 3× внутри Поколения** (`economy.test.ts` по всему
   каталогу); новый множитель, стоящий на отдельных Моделях, ломает лестницу (шаг доходной лестницы на длинных ростерах
   ≈3,02 — множитель ≥3 на одну Модель его переворачивает); любое изменение лестницы — через `tools/sim.ts`.
4. **Ни ключа AA, ни живых запросов AA.** `aa-snapshot.json` только через `npm run sync:aa`; бэкенда нет — все серверные идеи
   (рейтинги, облачные сейвы) отпадают.
5. **Русский словарь `CONTEXT.md`** (запрещённые синонимы из `_Avoid_` проверяются тестами `economy.test.ts` по глоссарию
   и `quips.test.ts` по репликам). Новый концепт — сначала строка в `CONTEXT.md`, потом код.

Решения ADR, закрывающие варианты:
- **ADR-0004:** ручные кластеры/слоты Моделей отклонены (комбинаторика, миграция, «один правильный ответ из вики»);
  инфраструктура GPU как глобальные множители — отклонена (запрещённые синонимы, дублирует Compute и Перки);
  отдельная сущность «реликвия» вместо Перка — отклонена; **голый +X% за Престиж отклонён как петля положительной связи**;
  бесконечные ступени Апгрейдов Модели после 100 и коллекция Флагманов — отложены (не отклонены).
- **ADR-0006:** Температура как покупаемый Апгрейд отклонена («множитель без решения»), шкала без инерции отклонена,
  `globalMult` не должен читать `now`.
- **ADR-0001:** баланс только от Ранга; скорость AA не влияет на Доход; ×1000 на Поколение; Модели — только из сидов;
  обновление данных = релиз.
- **ADR-0002/0003/0007:** новые UI-элементы поверх Сцены — с собственной подложкой; пиксельный шрифт только для чисел
  (через `Num`/`formatNumber`); цвета только `var()`; 8 акцентов Поколений зафиксированы.
- **ADR-0005:** Престиж без вспышки, фоточувствительность; новый «момент» Престижа — через те же фазы 2,8 с.
- `CODING_STANDARDS.md`: переход = `(GameState) => GameState` с тем же объектом при отсутствии изменений; все деньги —
  в `src/economy/`; один такт 50 мс; один путь записи (`SAVE_INTERVAL_MS`); никаких новых таймеров, кроме одноразовых.

## 7. Точки расширения (где слой подключается дешевле всего)

| Идея | Куда вешается | Цена |
|---|---|---|
| **Второй слой Престижа** (над Compute: сброс Compute/Поколений за новую валюту) | `prestige()` + `computeGain` в `catalog.ts`; новые поля в `GameState` (`валюта`, `счётчик`, список трат); множитель в `globalMult` (там сейчас Compute × кристаллы × налог × Испытания — естественное 5-е слагаемое); потолок Compute (`prestigeDivisor`) и единый `LAST_GENERATION` | средняя (миграция + модалка Престижа + `ShopColumn`) |
| **Ветка исследований / дерево** (выбор вместо «всё куплено») | новый `kind` в `Perk`/`PerkEffect` (дискриминированный union) + `perkEffects(owned)`; слоты — через существующий `perks[]` без bump; ограничение «выбери N из M» нужно **в `buyPerk`** | низкая-средняя; запретить «купить всё» (уйти от 437 Compute) |
| **Новая валюта / ресурс, добываемый вручную** (мини-игра) | отдельный слой как `crystal.ts` (чистая функция `(state, now)`), расписание в `advanceTime` рядом с `advanceEvents/advanceGlitches/collectCrystals`, сбор — action в сторе | средняя; `advanceTime` — единственная точка с `now`/`rnd` |
| **Мини-игра на Золотом Токене** (сделать «поимку» необходимой) | `events.ts:eventMultiplierFor/surgeMultFor/clickMultiplierFor` — добавить условие `caught`; `EVENT_TABLES`/`RED_TABLES` — таблицы `kind → spec`; новый вид — новое поле в `EVENT_KINDS` | низкая; `eventCaughtAt` уже в состоянии |
| **Выбор вместо покупки «подряд»** (доли ограниченных слотов: один Забег = один выбор из 3) | `Upgrade` — дискриминированный union в `upgrades.ts`: `isUpgradeUnlocked`, `modelBaseIncome`; `challengesDone` как образец «забег с условием» | низкая (поле как `activeChallenge`) |
| **Испытания Забега** (расширить с 2 до N, добавить условия) | `challenges.ts:CHALLENGES/ChallengeDef['id']` + проверки `activeChallenge === 'x'` в `modelBaseIncome/clickValue/advance`; награда сейчас константа 10% | низкая; нужен `migrate`-кламп id |
| **Цели/Вехи Забега после Пок.0** (контент для 1–4-минутных Забегов) | `milestones.ts:MILESTONES` (таблица `check` + `units`) | очень низкая |
| **Конец игры** (причина играть после Пок.7) | `isContentFinale`, `prestige()` — не блокировать на финале, а переводить в «петлю» (кольцо Поколений с множителем); `maxGeneration` уже хранится | средняя; затрагивает `economy.test.ts`/сейв |
| **Протухание Моделей** (идея 06-heretic №1) | новое поле на Модель в `GameState`; `modelBaseIncome` | средняя, **красная зона**: инвариант 3 |
| **Оффлайн-лотерея** (06-heretic №3) | поверх `applyOffline`, отдельный слой; **красная зона**: инвариант 2 | средняя |

Горячий путь: `modelBaseIncome` зовётся на каждую Модель каждый тик (до 19 раз, 20 Гц); новый множитель обязан быть дешёвым
(кэш по ссылке на список, как `hasUpgrade`/`perkEffects`). Любой новый множитель — отдельная функция в одном из файлов
`economy/` и **одна** строка в `globalMult` или `modelBaseIncome`; порядок множителей неявный — тестировать числами.

## 8. Слабые места текущей глубины (приоритетно)

1. **Кампания слишком короткая и сходится к конвейеру:** 8 Поколений за 15–30 мин, 7 из них ≈ 1–4 мин; Compute-петля
   (1%/Compute) сжимает время всё сильнее. Решения в Поколениях 2–8 нет, только числа.
2. **Нет scarcity:** все Перки куплены к 3–4 Престижу; «Наследие» (220 Compute) вообще ничего не делает; нет выбора «или-или».
3. **Продвинутые системы (Глюки, Восстание, Лобби, комбо, Лицензия) не успевают проявиться** в Забегах 1–3 мин; три из
   четырёх Событий не требуют поимки.
4. **Температура — единственное живое решение, но схлопывается** в «верни ползунок»; безопасный режим 0,2 даёт 80% выгоды.
5. **Финал без цели:** нет сброса-петли, Compute нечем тратить, Испытания на финале закрыть нельзя.
6. **Оптимальная стратегия не требует знания игры:** «кликай + покупай подряд + сразу Престиж».
